3. 流水线：吞吐、时延、显存

模型 L 层切成 P 个 stage，stage 有序 ⇒ 宿主必须构成 ISL 图上的一条路径。

- 每 stage 服务时间 t_s = L_s · t_layer / c_s

- 1F1B 稳态吞吐 R = M·b / [ (M+P−1)·max_s t_s + Σ hops ]

—— P·M/(M+P−1) 是它在均衡切分下的形状（LAB-47 用的形式）

- 单序列 TPOT = Σ_s t_s + Σ hops

关键修正：hop 预算不是 P 跳，是往返。 采样出的 token 必须回到 stage 0 才能

走下一步。1×P 的沿轨弧上，回程不是一跳而是 P−1 跳，所以每 token 付

2(P−1) 个沿轨跳。LAB-47 按 P 跳算，低估了约 2 倍。P=10 时：

```

沿轨 1×10 : 42.0 ms 计算 + 9×6.571 前向 + 9×6.571 回程 = 160.3 ms

蛇形 5×2 : 42.0 ms 计算 + (8×2.014 + 1×6.571) 前向 + 1×6.571 回程 = 71.3 ms

```

偶数列的蛇形块把回程收成一跳，这是它赢的机制，不是常数调优。

显存（PipeLive 原文公式）：

```

MaxBlocks(i, L) = ⌊ (M_i·u − L·W) / (L·P_blk) ⌋

B_shrink = min_i MaxBlocks(i) 可行性判据 B_used ≤ B_shrink

```

层切分必须是堆叠因子 k 的整数倍（PipeLive 第 6.2 节），所以 80 层 / k=4 只有

20 个可切单元，P 不整除 20 时切分不均衡、吞吐低于闭式值（tests/test_perf.py

里有这条的断言）。

24 GB 可用显存 × 0.9 下，140 + 42.9 = 182.9 GB 的模型要求 P ≥ 10。这是硬下界。

一次 stage 交接（P=10、KV 4.29 GB、100 Gbps）：

```

stop-and-copy KV : 368 ms 传输 + 20 ack + 11.1 cutover = 399 ms

增量补丁（2 轮收敛） : 残余 0.007 ms + 20 ack + 11.1 cutover = 31.1 ms ← 12.8×

```

ISL 争用按每 slot max-min 公平：一条流在被 n 条流共享的链路上拿 B/n。

一次 J 跳的批量跳会把 P 份 KV 复用到同样的 J 条链路上，所以有效带宽退化到

B/min(J,P)——批量化不是免费的，跳距必须对着链路速率选（见 E6）。

5. 删掉了什么（以及后果方向）

删掉后果方向
姿态 / 帆板入射角无功率时间被低估约 15 个百分点（LAB-67 实测）高估我们的成绩，需注意
电池 SoC 动态（c_e 当常数）"扛过去 vs 搬走"不是跨时段权衡E3 用扫参覆盖
半影10–160 s 的瞬态不出现影响很小
地球扁率、大气阻力、位保机动长期相位漂移3 轨窗口内可忽略
prefill/decode 混合、请求到达过程只报稳态 decode不报 TTFT
slot 内排队动态交接在其起始 slot 内定价10 s slot ≫ 0.4 s 交接
星地链路 / 用户侧只做星上放置与 SCOPE 的分工

第一条最重要：本文所有"无功率"数字都只算几何蚀期，是下界。 把姿态放回来会让

静态放置更差、迁移收益更大，所以本文的结论方向是保守的。
