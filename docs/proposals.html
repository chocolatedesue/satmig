四个方案

每个方案按要求写成三段：场景 / 谁 / 什么约束 / 做不到什么 → **已有做法 X 因为哪个

假设不成立而失效 → 我提出 Y，在某指标上相比 X 改善多少**。

所有"改善多少"都是 python -m satmig all 的输出，配置与产物在 configs/ 与

results/。基线一律是 conveyor（LAB-47 的 baseline），除非另注。

---

方案 1：EPH —— 用确定性蚀期预报把交接从"周期盲搬"变成"截止期驱动的批量跳"

场景 / 谁 / 约束 / 做不到什么

一个 LEO shell 的单轨道面上跑一条 P 段流水线的 LLM 推理服务。编排器知道每颗星

的蚀期时刻表（轨道几何决定，可提前一整年算出），但**受制于"stage 有序 ⇒ 宿主必须

构成 ISL 图上一条连续路径"，它做不到**把单个 stage 从光照弧末端拎到弧首——那会

把链拆开。于是它只能整块平移，而整块平移的次数直接决定了切换停顿的总量。

已有做法 X 及其失效的假设

- X₁ = SpotServe 的中断协调器：假设抢占不可预报，所以只有 30 s 宽限期，

只能 JIT 地搬。卫星上宽限期是 3050 s 量级（LAB-67 实测 p50），把它当 30 s 用

等于扔掉四个数量级的提前量；更要紧的是"不可预报"意味着权重无法预铺，于是每次

交接都要搬 14 GB 权重并做一次全局通信组重建。

- X₂ = LAB-47 的 conveyor：假设"每 T/N 必须平移一跳"。但这只在光照弧刚好装满

流水线时才是必须的。弧宽 13.8 而 P=10 时有 3.8 格余量，这些余量被白扔了。

我提出 Y

eph：(a) 触发时刻按 SCOPE Eq. 3 从蚀期入口反推；(b) 跳距取弧余量，一次跳

slack+1 格，用一次 cutover 换掉 slack+1 次；(c) K 条流水线的触发阈值按

k·(T/N)/K 错相；(d) 权重后台预铺、只搬 KV，走 PipeLive 增量补丁（脏集几何收敛）

+ CONNEX 纪元路由的 pair-local cutover；(e) 跳距对链路速率求解，见方案 4 的 E6。

读法：吞吐几乎不动（三者都能把 stage 保持在光照里），赢的是开销：事件数 5.0×

更少、停顿 62× 更小。停顿的 12.8× 来自增量补丁替掉 KV 的 stop-and-copy

边界：eph 只在自己的面内滑动。当同面还有别的流水线占着落点时它会被卡住——

E2 里 K≥2 时它反而输给 conveyor（546 vs 670 tok/s，K=8）。这不是调参问题，是方案 3

存在的理由。

方案 2：紧凑蛇形嵌入 —— 沿轨链在交互式时延预算下根本不可行

场景 / 谁 / 约束 / 做不到什么

同一个 shell 上服务交互式 LLM 推理（TPOT SLO 80–100 ms）。服务提供方受制于

两条同时成立的硬约束：星上显存 24 GB ⇒ 182.9 GB 的模型至少要切 10 段；单跳沿轨

ISL 传播 6.571 ms 且回程也要走 P−1 跳 ⇒ 时延随 P 线性涨。它做不到同时满足

这两条——可行域是空的。

已有做法 X 及其失效的假设

X = 把流水线摆成一串 ISL 邻居（1×P 沿轨弧）。这是地面 PP 的默认几何（机内/机架内

邻居间时延同质），也是 LAB-47 的模型。失效的假设有两条：

1. "stage 间一跳的代价与方向无关"。在 72 面 shell 上跨面一跳只有 2.014 ms，

是沿轨的 1/3.26。地面上没有这个各向异性，所以没人建模它。

2. "回程是一跳"。LAB-47 按 P 跳算 TPOT。实际上采样 token 要回到 stage 0，

开放弧上回程是 P−1 跳，所以是 2(P−1) 跳。这一条把 LAB-47 的时延低估了约 2 倍。

后果（E4，可直接读表）：

我提出 Y

eph_compact：把 stage 链嵌成 w × ⌈P/w⌉ 的蛇形（boustrophedon）块——列内走

便宜的跨面跳，只在换列时付一次沿轨跳。并且取偶数列，这样最后一个 stage 落在第一个

旁边，回程收成一跳。这不是常数优化，是把"有序链占连续弧"这条拓扑约束从一维推广

到二维后自然出现的最优形状。

最重要的一条不是倍数，是可行性：在 80–160 ms 这个交互式区间里，沿轨放置**没有

任何可行的 P**（显存要 ≥10，时延只给 3–9），蛇形放置把可行窗口开到 P ∈ [10, 30]。

代价：蛇形块跨 w 个轨道面，而各面 β 不同 ⇒ 蚀期时刻不同步，光照弧不再是一个

共同平移的整体。这就是方案 4 里"按面带而不是按单面排序"的由来。

方案 3：能源空闲度 + 跨面重定位 —— 多流水线争用不是带宽问题，是光照弧占用问题

场景 / 谁 / 约束 / 做不到什么

热点服务区上空（SCOPE 的设定）只有少数几个轨道面可用，K 条流水线多租户共享它们。

调度器受制于"每颗星只是一个加速器"（两个 stage 共址就互相砍半算力，且显存本来

就装不下），它做不到在 Σ P_k 超过这几个面的光照弧总容量时还保持性能——而它也

不知道该先让谁走。

已有做法 X 及其失效的假设

- X₁ = Llumnix 的空闲度调度：F = (M − ΣV)/B，观测到空闲度变差才迁。卫星上

"观测到算力掉了"意味着宿主已经进本影了——正是 Llumnix 自己要消除的 preemption

loss，被反应式触发重新引入。

- X₂ = LAB-47 的猜测："K 条流水线的交接时刻天然对齐 ⇒ 迁移风暴"。这条不成立：

单跳 lockstep 平移里每个 stage 走各自独立的链路，6 条流用 6 条不同的链，100 Gbps 下

峰值链路流数恒为 2（E2 实测），ISL 从不饱和。

- X₃ = eph（方案 1）：面内批量跳在同面有邻居时找不到落点，退化到不动 ⇒ stage

被留在暗区。

我提出 Y

eph_freeness：(a) 把 Llumnix 的显存空闲度换成可预测的能源空闲度

F_energy = t_到蚀期 + E_bat/P_cmp——卫星上这个量是解析已知的，不需要观测；

(b) 落点候选扩展到相邻轨道面，按 F_energy 最大、搬运字节最小挑；

(c) 落点内的 stage→宿主映射用 SpotServe 的 KM 二分图匹配，让已驻留权重的星继续

拿同一个 stage；(d) 准入顺序按 SCOPE Eq. 2 的价值密度。

方案 4：双时间尺度 —— 面选择是周级慢变量，而"免费的面"是季节性的

场景 / 谁 / 约束 / 做不到什么

星座运营方要为长期负载规划放置。它受制于"β 角以 66 天为周期慢变"（LAB-67），

做不到用逐 slot 重优化来利用面间异质性——那会把一个周级决策以秒级频率反复推翻，

churn 掉所有收益。

已有做法 X 及其失效的假设

- X = 连续再平衡（Llumnix / AlpaServe 一路）：假设资源池同质，好坏只由当前

负载决定。卫星上不成立：同一 shell 同一时刻，各面蚀占比从 0% 到 37.2%，而且

|β| > 67.0° 的面完全不进本影——放在那儿的流水线一次都不用迁。

- X 的第二个假设："好面的集合是稳定的"。也不成立：它取决于太阳赤纬，**近至日点

才存在，近分点为零**。

我提出 Y

two_timescale：外层按 β 角对"面带"排序（不是单面——紧凑块跨 w 个面，必须按

带内最差成员排，否则最好的面被摆在一个会进蚀的带边上，min 算子立刻吃掉优势），

只在 β 周期尺度重规划；内层沿用 eph_freeness。

三条结论：

1. 近至日点可以完全不迁移（事件数 13.5/h → 0），吞吐还高 46%。

2. 这是季节性的：近分点无蚀面数归零，two_timescale 退化成 eph_freeness。

按一个历元标定迁移容量的规划器，在另一个历元会错 100%。

3. 按单面排序是个陷阱：eph_freeness 在无蚀面存在时反而迁得更多

（9260 处 5.34/h，比分点的 0.94/h 高 5.7×），因为它把带跨在了无蚀面与重蚀面之间。

按带排序才拿得到那个 0。

顺带：E3 和 E6 两条"诚实性"结论

E3（扫 c_e）：static 的吞吐从 42.3（c_e=0）涨到 85.0（c_e=1），而所有迁移

策略恒定。所以整个迁移问题只在电池扛不住满功率计算时才存在——这正是 LAB-67 待办

第 1 条要标定的那个数。而 eph_freeness 相对 conveyor 的 +13% 与 c_e 无关，

因为它来自紧凑放置而非能源。两部分收益是可分离的。

E6（扫 ISL 速率）：单跳 lockstep 平移让每个 stage 独占整条链路，conveyor 在任何

速率下都不误期。但**批量 J 跳会把 P 份 KV 复用到同样的 J 条链路上，有效带宽退化

到 B/min(J,P)**——所以跳距必须对着链路速率求解（已实现）。修正后 10 Gbps 起零误期；

2 Gbps 以下（此模型尺寸下）KV 活迁移在时限内不可行，必须退回重算或接受降额。

**LAB-47"100 Gbps 下带宽不是瓶颈"成立，但余量是对着 ~11 s 的交接时限，不是 260 s 的

跳周期。**
